# Как запускать обучение

Пошаговая инструкция для игрока. Разовая настройка второй машины —
один раз, дальше только пункты «генерация» и «обучение».

Разделение труда: **генерация датасета — работа процессора**, обучение —
видеокарты. Обе части быстрее на второй машине, но узкое место —
именно генерация.

## Разовая настройка второй машины

### 1. Клонировать репозиторий

```powershell
git clone https://github.com/Deokti/tempocue-vision-model.git C:\PROJECTS\tempocue-vision-model
cd C:\PROJECTS\tempocue-vision-model
```

### 2. Создать окружение и поставить проект

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
```

Нужен Python 3.12. Проверить: `python --version`.

### 3. Поставить PyTorch с поддержкой видеокарты

Это единственный шаг, где возможны неожиданности: RTX 50-й серии нужна
сборка с новой версией CUDA.

```powershell
.venv\Scripts\python -m pip install torch --index-url https://download.pytorch.org/whl/cu129
```

Проверка — обязательная, до всего остального:

```powershell
.venv\Scripts\python -c "import torch; print(torch.__version__, torch.cuda.is_available(), torch.cuda.get_device_name(0))"
```

Должно напечатать версию, `True` и имя видеокарты. Если `False` —
обучение пойдёт на процессоре в десятки раз медленнее; в этом случае
пришли мне вывод команды, разберёмся с версией CUDA.

### 4. Скопировать кэш ассетов

Папку `data\` с этой машины скопируй целиком (флешка или сеть):

```
C:\PROJECTS\tempocue-vision-model\data\
```

Она не в git намеренно — это кэш. Без копирования инструменты скачают
всё сами, но зеркало Community Dragon медленное и рвётся.

## Генерация датасета

```powershell
.venv\Scripts\python tools\generate_dataset.py --count 4000 --seed 1 --out out\dataset-4k
```

- `--count` — сколько кадров. Ориентир: 4000 кадров ≈ 24 000 значков.
- `--seed` — фиксирует набор: одинаковый seed даёт одинаковый датасет.
- Время: на этой машине около 2,4 с на кадр, на второй ожидаемо быстрее.
  4000 кадров — порядка полутора-двух часов; можно оставить на ночь.
- Место: PNG 320×320 занимает ~150 КБ, 4000 кадров ≈ 600 МБ.

После генерации **посмотри `out\dataset-4k\contact-sheet.png`** — если
кадры однообразны или пусты, дальше идти нельзя.

## Обучение

Сначала короткий прогон — проверка, что всё живо:

```powershell
.venv\Scripts\python tools\train_detector.py --dataset out\dataset-4k --epochs 2 --out out\detector-smoke
```

Смотри первые строки: устройство должно быть `cuda`. Если `cpu` —
вернись к пункту 3 настройки.

Настоящий прогон:

```powershell
.venv\Scripts\python tools\train_detector.py --dataset out\dataset-4k --epochs 40 --batch-size 16 --out out\detector-01
```

- `--batch-size` — при 16 ГБ видеопамяти можно смело 16–32; если
  выскочит `CUDA out of memory`, уменьшай вдвое.
- `--epochs 40` — ориентир. Если к 40-й эпохе полнота ещё растёт,
  запусти следующий прогон длиннее; если перестала расти на 20-й —
  дальше только трата времени.
- Прерывать можно смело: `last.pt` и `best.pt` пишутся каждую эпоху.

## Что смотреть в результате

Каждая эпоха печатает строку:

```
эпоха  12: потери 0.031/0.045, точность 0.812, полнота 0.774, ошибка центра 1.42 px, 38 с
```

- **потери обучения / проверки** — падают обе: хорошо. Проверочные пошли
  вверх при падающих обучающих — переобучение, останавливай.
- **точность** — какая доля найденного действительно значки.
- **полнота** — какую долю значков нашли. Главное число ступени.
- **ошибка центра** — на сколько пикселей мимо. Ниже 2 px — отлично.

В каталоге прогона останутся `report.json`, `curves.png`,
`predictions.png`, `best.pt`, `last.pt`.

## Что прислать мне после прогона

Три маленьких файла (килобайты и картинки, не веса):

1. `report.json` — все числа по эпохам;
2. `curves.png` — кривые;
3. `predictions.png` — предсказания глазами.

Положи их куда угодно на машине разработки и скажи путь. Веса присылать
не нужно: для приёмки понадобится ONNX, и его мы соберём отдельным
шагом уже по этим числам.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `torch.cuda.is_available()` → False | Другая сборка CUDA; пришли вывод проверки |
| `CUDA out of memory` | Уменьшить `--batch-size` вдвое |
| Полнота стоит на нуле, потери падают | Прислать `report.json` — это признак, что сеть учит не ту задачу |
| Обучение оборвалось | Просто перезапусти; веса последней эпохи в `last.pt` |
| Генерация падает на битом файле | Инструмент сам удаляет битый файл кэша, повтори команду |
| `.venvScriptspython: command not found` | Это Git Bash: пиши `.venv/Scripts/python` с прямыми слэшами |
| Всё тормозит, диск шумит | Проект лежит в OneDrive — перенеси в несинхронизируемую папку |

## Порядок при следующих патчах Riot

Датасет привязан к патчу через кэш `data\cdragon\<патч>\`. При новом
патче: скопировать свежий кэш, перегенерировать датасет, обучить заново.
Модель от этого не устаревает структурно — меняются только данные.
