# Правила написания кода

Цель — чтобы через полгода код читался как текст, а не как археология. Правила
короткие и с причинами: правило без причины не соблюдается.

## Откуда взяты правила

У Python есть официальные стандарты, и мы не изобретаем свои поверх них:

| Стандарт | О чём | Как соблюдаем |
|---|---|---|
| **PEP 8** | стиль: отступы, длина строки, пробелы, имена | принуждает `ruff format`, не обсуждаем вручную |
| **PEP 257** | докстринги: что и как писать | правила ниже |
| **PEP 484 / 585 / 604** | подсказки типов (`list[str]`, `int \| None`) | в публичных сигнатурах |
| **PEP 20 (Zen of Python)** | принципы: явное лучше неявного, простое лучше сложного, плоское лучше вложенного, читаемость важнее всего | правила ниже — это его применение к нашей задаче |

Разделение труда: **механику принуждает инструмент, смысл — этот документ.**

## Инструмент

`ruff` — линтер и форматтер в одном, настроен в `pyproject.toml`. Он заменяет
связку black + flake8 + isort: одна зависимость вместо трёх и на порядок
быстрее.

```powershell
.venv\Scripts\python -m ruff format .    # отформатировать
.venv\Scripts\python -m ruff check .     # проверить
```

**Статической проверки типов (`mypy`) у нас нет намеренно.** Код вокруг numpy
плохо ложится на статический анализ: форма и dtype массива важнее их типа, а
`np.ndarray` статически ничего о них не говорит. Подсказки типов у нас для
читателя, а не для проверяющего. Пересмотреть, если появится сложная модель
данных, где ошибка типа реальна.

## Структура: библиотека против инструмента

- **`src/tcvm/` — чистая библиотека.** Никакого `print`, `argparse`, записи
  файлов и путей к чужим репозиториям. Только вычисления над явными
  аргументами.
- **`tools/` — оболочка.** Разбор аргументов, значения путей по умолчанию,
  печать, сохранение картинок и отчётов.

Проверка на месте: если функцию нельзя вызвать из другого скрипта, потому что
она печатает или знает конкретный путь, — она лежит не в том слое.

Пакет ставится в окружение один раз, и тогда инструменты импортируют его
обычным образом, без правки `sys.path`:

```powershell
.venv\Scripts\python -m pip install -e .
```

## Числа

**Каждое число в коде — либо именованная константа с происхождением, либо
параметр.** Магическое число без объяснения запрещено: через месяц никто не
вспомнит, почему `10`, и никто не решится его изменить.

Происхождение бывает трёх видов, и его пишут рядом:

- **измерено** — со ссылкой на документ (`INNER_RADIUS = 10.0` отрезает
  командное кольцо; ширина кольца измерена в сверке отрисовки);
- **выбрано** — с обоснованием (`SEARCH_RADIUS = 6` — дальше значок за 125 мс
  не уходит);
- **подобрано** — с указанием, каким прогоном.

## Функции

- Одна функция — одна мысль. Ориентир: помещается на экран, ~40 строк.
- **Не больше пяти позиционных аргументов.** Больше — группировать в
  `dataclass`. Так появился `RenderParams`: восемь параметров отрисовки в одном
  замороженном объекте вместо восьми аргументов подряд.
- Функция возвращает данные, а не печатает их. Печатает вызывающий из `tools/`.
- Ранний выход вместо вложенности: проверил условие — вышел, а не завернул
  остальное тело в `else`.

## Данные

- `dataclass(frozen=True)` для наборов значений. Класс с поведением заводить
  только тогда, когда у данных действительно есть своё поведение.
- `pathlib.Path` вместо строк-путей: он умеет `/`, `.exists()` и не ломается на
  разделителях.
- У numpy-массивов явный `dtype`, а форма — в докстринге, если она неочевидна:
  `(высота, ширина, 4)` сообщает больше, чем `np.ndarray`.
- Векторизация вместо циклов по пикселям. Цикл по конфигурациям перебора —
  нормально; цикл по 400 000 пикселей — нет.
- `.copy()` при возврате наружу, если исходный буфер может исчезнуть (чтение из
  закрываемого архива — ровно этот случай).

## Имена

- `snake_case` для функций и переменных, `PascalCase` для классов,
  `UPPER_SNAKE` для констант — PEP 8.
- Полное слово лучше сокращения: `champion`, а не `ch`. Исключение —
  общепринятая математическая запись в узком контексте: `ncc`, `dx`, `dy`,
  `cx`, `cy`.
- Имя выражает предмет, а не механизм: `noise_floor`, а не `data2`.
- Имена кода — на английском, тексты для человека — на русском.

## Комментарии и докстринги

- Докстринг у каждого модуля и каждой публичной функции: **что делает и зачем**,
  а не как. Модульный докстринг — самое ценное место в файле: он объясняет,
  зачем файл существует.
- Комментарий объясняет причину, ограничение или неочевидный инвариант.
  Комментировать синтаксис не нужно.
- Термин при первом употреблении — по-русски и общепринятым английским словом.

## Ошибки

- Пустой `except` запрещён. Ловим конкретный тип и делаем с ним что-то
  осмысленное.
- Падать рано и с понятным сообщением: `crop_centered` бросает `ValueError` с
  координатами, а не возвращает молча обрезанный массив.
- Повтор при ошибке — только для сети, с конечным числом попыток.

## Воспроизводимость

Специфика нашей работы: результат — это числа в отчёте, и они должны
получаться снова.

- Фиксированный seed везде, где есть случайность.
- Версия внешних данных — в пути кэша **и** в отчёте (у нас — версия патча).
- Инструмент в конце печатает, куда положил результат.
- Результаты, датасеты и веса в репозиторий не коммитятся.

## Рефакторинг

- **Правило трёх:** дублирование терпимо дважды. На третий раз — выносим.
- Не вводить слой, абстракцию или конфигурацию «на будущее». Только под
  существующую надобность.
- Рефакторинг — отдельным коммитом от изменения поведения. Смешанный коммит
  невозможно прочитать: непонятно, где переезд, а где новая логика.
- Сначала заставить работать, потом заставить читаться — но «потом» не длиннее
  одного коммита.

## Тесты

Честно: **автоматических тестов пока нет, это записанный долг.**

Что подлежит тестам в исследовательском коде — места, где ошибка **тихая**:

- чтение форматов (декодирование BGRA, stride, разметка);
- метрика: копия даёт `1`, независимый шум — около `0`;
- маски: число пикселей и симметрия.

Что тестами не покрывается: исследовательские инструменты целиком. Их проверка
— глазами по картинкам, и это записано в `AGENTS.md` как обязательный шаг.

## Проверка перед коммитом

```powershell
.venv\Scripts\python -m ruff format --check .
.venv\Scripts\python -m ruff check .
```
