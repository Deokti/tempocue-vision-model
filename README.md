# tempocue-vision-model

Обучение собственной модели распознавания миникарты League of Legends для
[TempoCue](https://github.com/) (приватный репозиторий приложения). Здесь живут
Python-инструменты: сверка отрисовки, генератор синтетики, обучение и экспорт в
ONNX. Приложение этот репозиторий не знает — граница между репозиториями один
артефакт: файл ONNX плюс файл соответствия.

## Контекст

Точка входа программы — `docs/own-model-plan.md` в репозитории TempoCue
(`C:\PROJECTS\tempocue`). Любая новая сессия начинается с `git pull` там и
чтения этого плана, раздела «Потолок собственной модели» в
`vision-improvement-plan.md` и записей TC-003…TC-010 в `known-issues.md`.
Решение, не записанное в документы, не существует.

Кратко: конвейер приложения берёт 45 чемпионов из 60 по корпусу при нуле ложных
и 58 мс на кадр. Модель должна закрыть оставшиеся пропуски (6 «без области» +
9 «с областью») и поднять устойчивость на движущемся чемпионе с 79 % кадров к
95 %. Архитектура — двухступенчатая: детектор центров (карта вероятностей,
шаг 4, канонические 320) отвечает «где», вложение (embedding, вырезы из родного
кадра) отвечает «кто», опознание — сравнением с векторами из актуального
Data Dragon. Обучение — на синтетике; реальные кадры — только приёмка.

## Данные

Корпус и записи лежат в основном репозитории и сюда не копируются:

- `...\tests\TempoCue.Vision.Tests\ReplayCorpus\*.tempocue-vision` — 12 кадров
  320×320 с ручной разметкой (60 чемпионов);
- `...\tests\TempoCue.Vision.Tests\ReplaySequences\*.tempocue-sequence` —
  записи ~24 кадров за ~3 секунды.

Оба формата — ZIP: `manifest.json` + сырые пиксели BGRA32. Читалка —
`src/tcvm/formats.py`.


```powershell

```

## Структура

| Путь | Что это |
|---|---|
| `src/tcvm/` | библиотека: форматы, дальше — отрисовка, генератор, обучение |
| `tools/` | запускаемые инструменты |
| `docs/` | методики и результаты ступеней; ступень без записи — несделанная |
| `out/`, `data/` | результаты и кэши, не под git |

## Ступени (из own-model-plan.md)

1. Каркас репозитория + **сверка отрисовки** — `docs/render-verification.md` ← сейчас здесь
2. Генератор синтетики
3. Крошечный детектор «где» — обкатка цикла данные → обучение → ONNX → приёмка
4. Честное сравнение: конвейер / DeeperLeague / своя модель
5. Вложение «кто»
6. Гибрид в приложении

--stability/--sequence`, шесть числовых порогов (см. план).
